## OAuth и лимиты

`Authorization: OAuth <METRIKA_OAUTH_TOKEN>`: пробел после `OAuth` обязателен. Минимальные scope: `metrika:read` для счетчиков и чтения целей; `metrika:write` для создания цели и изменения настроек; `metrika:offline_data` для загрузки офлайн-данных. Не хранить токены в открытом виде или журнале. Лимиты API: 30 запросов/с с IP, 3 одновременных запроса на пользователя, 5000 запросов/сутки на пользователя (сброс по GMT), 200 запросов отчетного API за 5 минут; `429` требует замедления, а не частых повторов. [Авторизация](https://yandex.ru/dev/metrika/ru/intro/authorization), [квоты](https://yandex.ru/dev/metrika/ru/intro/quotas).

## Счетчик и цель

Сначала `GET /management/v1/counters`, затем `GET /management/v1/counter/{id}` и `GET /management/v1/counter/{id}/goals`. Для создания согласованной JavaScript-цели: `POST /management/v1/counter/{id}/goals` с `goal: {name: "Delivest completed", type: "action", conditions: [{type: "exact", url: "delivest_order_completed"}]}`. Строка `delivest_order_completed` — идентификатор события для `reachGoal`, `ea` и CSV `Target`; числовой `goal.id` из ответа нужен для управления целью и не подставляется вместо идентификатора события. Создание цели — операция записи и требует отдельного решения владельца счетчика. [Счетчики](https://yandex.ru/dev/metrika/ru/management/openapi/counter/counters), [цели](https://yandex.ru/dev/metrika/ru/management/openapi/goal/goals), [создание цели](https://yandex.ru/dev/metrika/ru/management/openapi/goal/addGoal).

## Офлайн-конверсия `completed`

CSV с заголовком `ClientId,Target,DateTime,Price,Currency`: `Target` — строка идентификатора цели, `DateTime` — прошедшее Unix-время в **секундах**; хотя бы один из `ClientId`, `Yclid`, `UserId`, `PurchaseId` нужен для привязки. Предпочтителен сохраненный `ClientId`; `UserId` пригоден лишь при ранее настроенной связи через `setUserID`, `PurchaseId` — при покупке, уже известной Метрике, а не любой UUID заказа. Между последним визитом и **обработкой** файла должно пройти не более 21 дня, поэтому нельзя откладывать загрузку до края окна. `Price` — десятичные рубли с точкой, сформированные из целых копеек без float; `Currency=RUB`. Для заказа без разрешенного идентификатора визита событие не выдумывать. Использовать один согласованный optimization target, не дублировать финансовый результат через несколько целей. [Передача офлайн-конверсий](https://yandex.ru/dev/metrika/ru/management/offline-conv), [условия привязки](https://yandex.ru/support/metrica/ru/data/offline-params).

Загрузка: `POST /management/v1/counter/{counterId}/offline_conversions/upload` как `multipart/form-data`, поле `file`; сохранить `uploading.id`. Статус: `GET /management/v1/counter/{counterId}/offline_conversions/uploading/{id}`. Файл UTF-8, максимум 1 ГБ, обработка до 3 часов. Успешный статус обработки не доказывает привязку к визиту; Яндекс отдельно предупреждает о неверных статусах привязки в отчетах — фактическую долю смотреть в интерфейсе счетчика «Загрузка данных». [Загрузка](https://yandex.ru/dev/metrika/ru/management/openapi/offline_conversions/upload_1), [статус](https://yandex.ru/dev/metrika/ru/management/openapi/offline_conversions/findById_1).

Ответ загрузки содержит `source_quantity` (исходные строки) и `line_quantity` (прошли валидацию). Статусы: `PREPARED`, `UPLOADED`, `EXPORTED`, `MATCHED`, `PROCESSED`, `LINKAGE_FAILURE`; отдельно сверять количество и привязку. API не обещает нам безопасную дедупликацию повторного файла. Для будущего outbox нужен ключ `order + destination generation + event`; после timeout исход неопределен: прежде чем повторять, сверить `uploading.id`/состояние и фактическую загрузку. Правила повторной отправки, исправления и возврата определить в пилоте. [Загрузка](https://yandex.ru/dev/metrika/ru/management/openapi/offline_conversions/upload_1), [статус](https://yandex.ru/dev/metrika/ru/management/openapi/offline_conversions/findById_1).

## Measurement Protocol (MP)

Для счетчика нужна включенная опция MP и отдельный секретный `ms`. Управление: `GET /management/v1/counter/{id}?field=counter_flags`, включение `PUT` с `counter.counter_flags.measurement_enabled=true`; токены читать `GET ...?field=measurement_tokens`, при необходимости генерировать/удалять по документации. Ответ с токенами не журналировать. [Управление опцией и токенами](https://yandex.ru/dev/metrika/ru/data-import/manage-protocol).

Отправка `POST https://mc.yandex.ru/collect`, `application/x-www-form-urlencoded`, UTF-8 URL encoding. Всегда `tid`, `cid`, `t`, `ms`; `cid` — строка неотрицательного целого, сохраняем как строку без потери точности. Просмотр: `t=pageview&dl=<URL>`. Событие: `t=event`; JS-цель дополнительно `ea=<goal identifier>`, ecommerce — `pa=detail|add|remove|purchase` и `pr1id`, `pr1pr`, `pr1qt` (или `pr1nm`); у `purchase` обязателен `ti=<order id>`, рекомендуется `tr=<total>`, `cu=RUB`. При включенном ограничении адресов `dl` обязателен и для события. `et` — Unix-секунды, не ранее 12 часов назад; событие должно попасть в период визита с учетом его таймаута, обогащение возможно только в течение 12 часов после конца визита. При отсутствии подходящего визита не создавать искусственный pageview. Пакет MP ограничен 1 МБ без сжатия; избыток может быть отброшен даже при HTTP 200, а ответ `<!-- OK -->` означает прием запроса, не запись события. Отложенное `completed` в MP может потеряться, поэтому для финальной конверсии предусмотрен отдельный офлайн-путь. [Загрузка MP](https://yandex.ru/dev/metrika/ru/data-import/measurement-upload), [ограничения MP](https://yandex.ru/dev/metrika/ru/data-import/measurement-about).

Отчет Метрики для сверки: `GET /stat/v1/data` с `ids`, `metrics` (не более 20), по необходимости `dimensions`, `date1`, `date2`, `limit`, `offset`; учитывать метаданные сэмплирования и не сравнивать частичный отчет с точным ledger. Пример запроса в [metrika.http](examples/metrika.http). [Метод отчета](https://yandex.ru/dev/metrika/ru/stat/openapi/data_1), [примеры](https://yandex.ru/dev/metrika/ru/stat/examples).
