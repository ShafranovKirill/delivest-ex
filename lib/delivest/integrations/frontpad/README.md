# Frontpad

CRM для доставки. Принимает заказы, присылает смену статусов вебхуком и отдаёт список товаров для сверки меню.

- Провайдер: `Delivest.Integrations.Frontpad`, ключ `:frontpad`
- Настройки: на филиал, `branch_info.crm.frontpad`
- Админка: `/staff/integrations/frontpad`

## Наши модули

| Модуль | Что делает |
|---|---|
| `Frontpad` | Реализация `Crm.Provider`: отправка заказа, ошибки, лимиты, каталог, вебхук |
| `Frontpad.Api` | HTTP-запросы `new_order`, `get_products` и `get_stops`, разбор ответов |
| `Frontpad.OrderPayload` | Заказ приложения → поля `new_order` |
| `Frontpad.AddressFields` | Единый адрес → `street`, `home`, `pod`, `et`, `apart` |
| `Frontpad.Fields` | Обрезка строк под лимиты Frontpad |
| `Frontpad.Webhook` | Обработка `change_status` |
| `Frontpad.Settings` | Ключ API, филиал Frontpad, токен вебхука, режим цен, `sync_stops` |
| `Frontpad.StatusCodes` | Коды статусов Frontpad ↔ статусы приложения |

## Подключение

1. Во Frontpad: «Настройки» → «Общие» → включить API.
2. Там же скопировать секрет и вставить его в админке в поле «API-ключ Frontpad». Код филиала Frontpad — в «ID филиала Frontpad».
3. Каждому товару, который продаётся в приложении, задать во Frontpad уникальный цифровой артикул и вписать его в товар приложения в поле «Артикул Frontpad».
4. Скопировать из админки ссылку вебхука и вставить её в настройки API Frontpad, потом перезапустить программу Frontpad.
5. В админке сопоставить коды статусов Frontpad со статусами приложения.
6. Включить «Передавать заказы во Frontpad».

## Как мы отправляем заказ

| Поле Frontpad | Откуда берём | Лимит |
|---|---|---|
| `secret` | `settings.api_key` | — |
| `affiliate` | `settings.affiliate` (филиал во Frontpad) | — |
| `product[i]`, `product_kol[i]` | артикул товара для `frontpad` из `product_external_ids` и количество | — |
| `product_mod[i]` | индекс родительского товара для модификатора | — |
| `product_price[i]` | цена со скидкой, только если включён `price_override` | — |
| `sale_amount` | вся скидка заказа одной суммой, если `price_override` выключен | — |
| `phone`, `name` | клиент заказа | 50 |
| `street`, `home`, `apart` | `address.street`, `address.house`, `address.apartment` | 50 |
| `pod`, `et` | `address.entrance`, `address.floor`, только цифры | 2 |
| `descr` | `Crm.OrderNotes`: домофон, комментарий к адресу, комментарий к заказу | 100 |
| `pay` | `cash` → `1`, `card_offline` → `2` | — |
| `datetime` | `cook_by`, `ГГГГ-ММ-ДД ЧЧ:ММ:СС` | — |
| `hook_status[i]`, `hook_url` | сопоставленные коды статусов и наш вебхук | 5 кодов |

Координаты, город и поля DaData Frontpad не принимает, поэтому мы их не отправляем.

### Ошибки

| Ошибка | Что делаем |
|---|---|
| `invalid_secret`, `api_off`, `invalid_plant`, `invalid_product_keys`, `invalid_certificate` | Сразу помечаем заказ ошибкой |
| `requests_limit` | Откладываем на 60 с |
| `cash_close` | Откладываем на 10 минут |
| Нет ключа API или артикула у товара | Сразу помечаем заказ ошибкой |
| Сетевые и прочие ошибки | Повторяем, до 7 попыток |

Между запросами к одному аккаунту выдерживаем 2 с (`config :delivest, Delivest.Integrations.Frontpad, request_interval_ms:`).

# API Frontpad

## Общее

- Запрос: `POST`, тело как у отправки HTML-формы (`application/x-www-form-urlencoded`), UTF-8.
- Адрес: `https://app.frontpad.ru/api/index.php?<метод>`
- Ответ: JSON.

### Лимиты

| Что | Лимит |
|---|---|
| Все методы | 30 запросов в минуту и не больше 2 в секунду |
| `get_products` | 1 запрос в час |

Автоматический перебор данных запрещён: запросы можно слать только в ответ на действия клиента. Frontpad советует защищать формы капчей или авторизацией. IP-адреса нарушителей блокируются.

### Общие ответы

| `result` | `error` | Значение |
|---|---|---|
| `success` | — | Успешно |
| `error` | `invalid_secret` | Неверный секрет |
| `error` | `requests_limit` | Превышен лимит запросов |
| `error` | `api_off` | API выключен |
| `error` | `invalid_plant` | API недоступен на текущем тарифе |

### Методы

| Метод | Что делает | Используем |
|---|---|---|
| `new_order` | Создать заказ | да |
| `get_products` | Список товаров с артикулами | да |
| `get_stops` | Стоп-лист | да, при включённой опции «Получать стоп-лист из Frontpad» |
| `get_client` | Клиент по телефону | нет |
| `get_certificate` | Проверка сертификата | нет |

## `new_order` — создать заказ

### Параметры

| Параметр | Обязательный | Описание |
|---|---|---|
| `secret` | да | Секрет API |
| `product[i]` | да | Артикулы товаров |
| `product_kol[i]` | да | Количество, индекс совпадает с `product` |
| `product_mod[i]` | | Модификатор: значение — индекс родительского товара в `product` |
| `product_price[i]` | | Цена товара. Работает только для товаров с опцией «Изменение цены при создании заказа» |
| `score` | | Баллы для оплаты |
| `sale` | | Скидка в процентах, целое 1–100 |
| `sale_amount` | | Скидка суммой. Можно передать только один тип скидки: `sale` или `sale_amount` |
| `card` | | Карта клиента, целое до 16 цифр |
| `street` | | Улица, до 50 символов |
| `home` | | Дом, до 50 символов |
| `pod` | | Подъезд, до 2 символов |
| `et` | | Этаж, до 2 символов |
| `apart` | | Квартира, до 50 символов |
| `phone` | | Телефон, до 50 символов |
| `mail` | | Почта, до 50 символов. Только при включённом автосохранении клиентов |
| `descr` | | Примечание, до 100 символов |
| `name` | | Имя клиента, до 50 символов |
| `pay` | | Код оплаты из справочника «Варианты оплаты» |
| `certificate` | | Номер сертификата |
| `person` | | Количество персон, 2 символа. Автосписание к нему не привязывается |
| `tags[i]` | | Коды отметок заказа, не больше 10 |
| `hook_status[i]` | | Коды статусов, о смене которых слать вебхук, не больше 5 |
| `hook_url` | | Адрес вебхука для этого заказа. Без него используется адрес из настроек API |
| `channel` | | Код канала продаж |
| `datetime` | | Предзаказ, `ГГГГ-ММ-ДД ЧЧ:ММ:СС`, не дальше 30 дней |
| `affiliate` | | Код филиала |
| `point` | | Код точки продаж |

Коды оплаты, отметок, статусов, каналов, филиалов и точек продаж смотрятся в справочниках программы Frontpad.

### Пример тела запроса

Пицца с двумя добавками (сыр и бекон) и сок:

```
secret=...&street=Мира&home=17&apart=6&phone=79000000001&name=Иван&descr=Быстрее!
&product[0]=10000&product_kol[0]=1
&product[1]=10001&product_kol[1]=1&product_mod[1]=0
&product[2]=10002&product_kol[2]=1&product_mod[2]=0
&product[3]=10003&product_kol[3]=1
&tags[0]=1&tags[1]=5
&hook_status[0]=3&hook_status[1]=4
```

Здесь `product_mod[1]=0` и `product_mod[2]=0` означают, что товары 1 и 2 — добавки к товару 0.

### Ответ

Успех:

```json
{ "result": "success", "order_id": "1000020", "order_number": "143" }
```

`order_id` — id заказа во Frontpad, по нему приходят вебхуки. `order_number` — номер заказа в программе.

Ошибки:

| `error` | Значение |
|---|---|
| `cash_close` | Смена закрыта |
| `invalid_product_keys` | Неверный массив товаров |
| `invalid_certificate` | Неверный или несуществующий сертификат |

Предупреждения: заказ создан, но часть данных не принята. Приходят в `warnings`.

| Ключ | Значение |
|---|---|
| `invalid_certificate` | Неверный сертификат |
| `invalid_datetime` | `invalid_format` — неверный формат, `too_long_period` — дальше 30 дней |
| `invalid_product_keys` | Индексы `product` с неверными артикулами |
| `invalid_tags` | Индексы `tags` с неверными кодами |
| `invalid_hook_status` | Индексы `hook_status` с неверными кодами |

```json
{
  "result": "success",
  "order_id": "1000020",
  "warnings": { "invalid_product_keys": { "0": "1", "1": "5" } }
}
```

## Вебхук смены статуса

Чтобы вебхуки приходили:

1. Указать адрес в настройках API Frontpad (обязательно). Для отдельного заказа его можно переопределить через `hook_url`.
2. Перезапустить программу Frontpad.
3. При создании заказа передать в `hook_status` коды нужных статусов.

При смене статуса Frontpad шлёт `POST` с JSON:

```json
{ "action": "change_status", "order_id": 12345678, "status": 3, "datetime": "2020-08-21 12:03:00" }
```

| Поле | Значение |
|---|---|
| `action` | Всегда `change_status` |
| `order_id` | `order_id` из ответа `new_order` |
| `status` | Код статуса из справочника клиента |
| `datetime` | Время смены статуса, местное |

У нас адрес такой: `/integrations/crm/frontpad/<webhook_token>`. Код статуса переводится в статус приложения по таблице из настроек филиала. Если код не сопоставлен, статус заказа не меняется, а в карточке заказа появляется предупреждение.

## `get_products` — список товаров

Отдаёт только товары с артикулом. Лимит — 1 запрос в час. Параметры: `secret`.

```json
{
  "result": "success",
  "product_id": { "0": "001", "1": "002" },
  "name": { "0": "Филадельфия", "1": "Калифорния" },
  "price": { "0": "250", "1": "350" }
}
```

Массивы связаны по ключу. Ещё может прийти массив `sale`: `1` значит, что к товару применяются скидки. При создании заказа Frontpad смотрит на текущую настройку в программе, поэтому это поле нужно только для корзины на стороне магазина.

Ошибка `invalid_products` — нет товаров для выгрузки. Мы считаем это пустым списком.

## `get_stops` — стоп-лист

Параметры и ответ такие же, как у `get_products`. Пустой стоп-лист:

```json
{ "result": "success", "error": "no_stops" }
```

## `get_client` — клиент по телефону

Циклический поиск клиентов запрещён.

| Параметр | Описание |
|---|---|
| `secret` | Секрет API |
| `client_phone` | Телефон. Поиск строгий, маски в программе и магазине должны совпадать |

Ответ: `name`, `street`, `home`, `pod`, `et`, `apart`, `mail`, `descr`, `card`, `sale` (скидка клиента), `score` (баллы).

```json
{ "result": "success", "name": "Иван", "street": "Мира", "home": "17", "pod": "1", "et": "2",
  "apart": "6", "mail": "mail@mail.com", "descr": "", "card": "4321", "sale": "10", "score": "100" }
```

Ошибка `invalid_client_phone` — неверный или несуществующий номер.

## `get_certificate` — проверка сертификата

Циклическая проверка запрещена. Параметры: `secret`, `certificate`.

| Тип сертификата | Поля ответа |
|---|---|
| На товар | `product_id`, `name`, `price` |
| На скидку в процентах | `sale` |
| На скидку суммой | `amount` |

```json
{ "result": "success", "product_id": "0001", "name": "Филадельфия", "price": "250" }
```

Ошибка `invalid_certificate` — неверный или несуществующий сертификат.
