# Слепок сайта для переноса с локального Delivest на прод

## Цель

Собрать витрину локально, скачать один файл из админки и загрузить его в админку другого инстанса. Источник и получатель работают на одной версии Delivest. После выбора файла импорт запускается сразу. Администратор получает результат с числом созданных и обновлённых записей либо сообщение об ошибке.

## Границы первой версии

- Один слепок содержит один филиал, его каталог и переносимые настройки витрины. На целевом инстансе администратор заранее открывает существующий филиал. Для первого запуска подойдёт пустой филиал.
- Переносим публичные сведения о филиале, расписание, способы получения заказа, зоны и параметры доставки. Из общих настроек переносим оформление витрины, логотип, баннеры и другие изображения, на которые ссылаются переносимые записи.
- Переносим категории, товары, цены, теги, группы модификаторов, модификаторы, связи, порядок и видимость. Для каждой записи переносим только явно перечисленные поля.
- Продовые заказы, клиенты, сотрудники, роли, платежи, остатки, стоп-листы, история, акции, подключения к внешним сервисам, внешние идентификаторы и секреты остаются в целевом инстансе. Домен, параметры окружения и ключи хранилища берутся из его конфигурации.
- Записи, отсутствующие в архиве, сохраняются. Общие настройки витрины действуют на весь целевой инстанс. Перед реализацией нужно проверить область действия каждого каталожного объекта. Если обновление общего объекта затронет другие филиалы, импорт отклоняется с указанием объекта. Для оформления область действия явно указывается на странице загрузки.
- Один формат для текущей версии. Полный дамп PostgreSQL остаётся отдельной операцией агента. Экран сравнения, миграции формата и синхронизация между сайтами в эту задачу не входят.

## Компоненты и реализация

### 1. Инвентаризация схем и ключей

Составить в коде явный перечень сущностей, полей, зависимостей и ссылок на медиа. Источники схем — `Delivest.Identity.Branch` и модули `Identity.Branch.*`, `Delivest.Franchise`, `Franchise.SettingsStore`, `Delivest.Delivery` и `Delivest.Net`. Для настроек, содержащих смесь публичных и служебных параметров, перечислить разрешённые вложенные ключи. Проверить обязательные поля и правила видимости по Ecto-схемам, миграциям и запросам витрины.

Для связей внутри архива использовать идентификаторы записей источника. На импорте сопоставлять исходные идентификаторы с целевыми. Существующий объект можно сопоставить по ключу только там, где подтверждены его уникальность и область действия в БД. Например, проверить индекс для `Product.slug` до использования в таком качестве. Для сущностей без подходящего ключа сохранять соответствие между ID источника и ID получателя в служебной таблице. Включить в уникальный индекс идентификатор исходной установки, целевой филиал, тип и исходный ID записи. Сохранять соответствия в той же транзакции, что и данные. При неоднозначном совпадении отклонять импорт.

### 2. Сервис экспорта и формат архива

Добавить серверный контекст `Delivest.SiteSnapshot` для экспорта и импорта. Для чтения и записи переиспользовать контексты проекта и Ecto changesets. Посмотреть `Delivest.Net.MenuExport` и существующий контроллер экспорта меню как пример выдачи файла из админки.

- Сформировать ZIP с `manifest.json`, `data.json` и каталогом `media/`. В манифест записать версию формата, идентификатор сборки Delivest, идентификатор установки и исходного филиала, список файлов, размеры и SHA-256. Использовать один и тот же идентификатор сборки для локального запуска и релиза, например SHA коммита серверного репозитория.
- Считать записи и связи в согласованном снимке БД. Для медиа собрать уникальные ссылки на `Delivest.Media.File` из переносимых записей. Скачать оригиналы сервером через `ExAws.S3` по bucket/key. Если объект отсутствует, завершить экспорт с ошибкой и указать запись, которой принадлежит файл.
- Собрать архив во временном каталоге и отдать его как скачиваемый файл. Ограничить размеры архива и файлов. Удалять временные файлы после передачи или ошибки.

### 3. Импорт

1. Принять архив во временное хранилище. Проверить версию сборки и формата, допустимый размер архива, количество записей, размер распакованных данных, допустимые имена файлов, типы файлов и контрольные суммы. Отклонять архивы с дублирующимися путями, абсолютными путями, выходом из рабочего каталога и симлинками. Проверить JSON, обязательные поля и ссылки между сущностями до записи данных.
2. Разрешить целевой филиал на сервере и проверить права. Сериализовать импорты, меняющие общие настройки одного инстанса. Составить внутренний план сопоставления объектов, проверить конфликты и область действия общих каталожных записей.
3. Загрузить оригиналы в целевой S3-бакет под новыми ключами через `ExAws.S3`. Повторно использовать ранее импортированное медиа, если содержимое совпадает и объект доступен. Ссылки в переносимых данных должны вести на целевые записи `Media.File`. Публичные URL формируются существующими функциями `Delivest.Media`. Превью поставить на генерацию через `Delivest.Media.Thumbnails` после коммита.
4. В одной транзакции `Delivest.Repo` применить настройки и каталог в порядке зависимостей. Сначала создать записи медиа и справочники, затем товары, цены, связи и ссылки в настройках. В транзакции повторно проверить условия сопоставления, которые могли измениться при загрузке файлов. Для записи данных использовать операции без отправки событий во внешние системы. После коммита обновить производные данные и кэш витрины там, где это требуется существующими контекстами.
5. При ошибке до коммита откатить изменения БД и убрать новые S3-объекты этой попытки. Если очистка не удалась, записать ключи в журнал для повторной очистки. Существующие медиа не удалять. По завершении очистить временные файлы и записать в аудит исполнителя, целевой филиал и результат операции.

### 4. Админка

Добавить раздел «Слепок сайта» к настройкам выбранного филиала в `DelivestWeb.Staff.BranchLive.Edit`. Показать название филиала и коротко описать, что входит в перенос. Кнопка «Выгрузить сайт» скачивает ZIP через отдельный контроллер в области `/staff`. Кнопка «Загрузить слепок» открывает выбор ZIP и запускает импорт после загрузки. Использовать стандартную загрузку Phoenix LiveView с прогрессом и блокировкой повторного запуска. Длительный экспорт или импорт выполнять вне процесса LiveView, чтобы закрытие страницы не обрывало уже начатый импорт.

Проверять права на просмотр и изменение данных филиала и на изменение общих настроек. Использовать существующие `StaffAuth`, `StaffActiveBranch` и ACL. Выполнять проверку на сервере на каждом входе, включая прямое обращение к контроллеру скачивания. Согласовать лимиты загрузки между Phoenix и обратным прокси и отобразить максимальный размер рядом с кнопкой.

### 5. Слепок всей франшизы

Кроме слепка одного филиала админка умеет переносить всю франшизу одним архивом. Раздел «Слепок франшизы» находится в настройках франшизы (`DelivestWeb.Staff.FranchiseLive.Index`) и доступен только администратору (`Identity.can?(staff, "admin")`).

- Архив содержит список филиалов и общие данные франшизы. В манифесте указывается `scope: "franchise"` и выбранные разделы; слепок одного филиала остаётся с `scope: "branch"` и совместим со старым форматом.
- Разделы выбираются галочками при экспорте: `storefront` (адрес, контакты, расписание, доставка и зоны), `catalog` (категории, товары, модификаторы и фото каждого филиала), `franchise` (бренд, реквизиты продавца, лояльность и юридические документы), `integrations` (CRM, фискализация, каналы, доставка, эквайринг и другие внешние сервисы). Нужно выбрать хотя бы один раздел.
- Импорт сопоставляет филиалы по сохранённому соответствию, затем по `slug`. Совпавшие филиалы обновляются, отсутствующие создаются; данные целевого инстанса, которых нет в архиве, не удаляются. Мягко удалённый филиал при совпадении восстанавливается. Код филиала при необходимости заменяется свободным.
- Общие интеграции переносятся только в разделе `integrations`. В архив попадают ключи ЮKassa, Zvonok, DaData и Яндекс Еды (кроме `client_id`/`client_secret`). Из-за секретов в интерфейсе показывается предупреждение о хранении архива как пароля.
- Импорт выполняется одной транзакцией под глобальной блокировкой, проверка прав и формата происходит на сервере. Ошибки сопоставления (конфликт имени или ссылки филиала, занятый код, общий каталог, зона другого филиала) откатывают весь импорт.

## Критерии приёмки и проверка

| Сценарий | Ожидаемый результат |
|---|---|
| Локальный экспорт и импорт в пустой филиал другого инстанса той же сборки | В админке и на витрине совпадают настройки, категории, товары, цены, модификаторы и порядок. Оригиналы фото доступны из целевого S3 |
| Повторный импорт того же архива | Количество записей и объектов медиа не увеличивается |
| Повторный экспорт после изменения цены и замены фото | Импорт обновляет тот же товар, сохраняет его целевой ID и показывает новое фото |
| Импорт в заполненный филиал | Заказы, клиенты, сотрудники и секреты сохраняются. Позиции вне архива остаются. Конфликт с общим каталогом другого филиала отклоняется |
| Неверная версия, повреждённый ZIP, недостающий файл, недопустимый путь | Отказ до изменений БД и S3 |
| Сбой записи в S3 или БД | Прежняя витрина доступна. Данные БД сохраняются, новые файлы не становятся частью витрины |
| Два одновременных импорта | Операции сериализуются, дубли не появляются |
| Недостаточно прав или подменён филиал в запросе | Сервер отклоняет скачивание и импорт |
| Экспорт всей франшизы с разделом «Интеграции» | В архиве есть настройки внешних сервисов, в интерфейсе показано предупреждение о секретах |
| Импорт слепка франшизы в другой инстанс | Филиалы сопоставлены по `slug`, существующие обновлены, отсутствующие созданы, данные вне архива сохранены |
| Повторный импорт слепка франшизы | Филиалы, каталог и медиа не дублируются, соответствия переиспользуются |
| Экспорт или импорт франшизы без прав администратора | Сервер возвращает отказ, раздел скрыт в интерфейсе |

Покрыть проверки архива, прав, повторного импорта и отката автоматическими тестами. Отдельно прогнать полный цикл на двух тестовых инстансах с разными БД и S3-бакетами и открыть витрину получателя. Перед ревью запустить `mix precommit` в `server`.

Связанная задача: [рефакторинг и исправления слепка всей франшизы](franchise-site-snapshot-refactor.md).
