# Задача: печать и фискализация (54-ФЗ)

Система автономная, без интеграции с POS-системами заведений. Своё фискальное ядро не пишем — свой слой абстракции поверх готовых провайдеров. Первый провайдер — АТОЛ Онлайн, документация API — [integrations/atol_online/README.md](../../lib/delivest/integrations/atol_online/README.md).

## Решения

| Вопрос | Решение |
|---|---|
| Основной провайдер | АТОЛ Онлайн (облачная касса), протокол v5, ФФД 1.2. Покрывает и онлайн-оплату, и оплату курьеру |
| Онлайн-оплата | ЮKassa — чеки через эквайринг, когда подключим онлайн-оплату |
| Второй облачный провайдер | OrangeData, Комтет — пока не делаем, архитектура должна позволять добавить |
| POS (iiko, r_keeper и др.) | Не интегрируемся |
| Какие заказы | Чеки только по заказам нашего приложения |
| Заведения на CRM | Настройка заведения `fiscalization: own \| external \| off`. При Frontpad или iiko — `external`, чеки на их стороне, мы не пробиваем |
| Дубли | Один платёж — ровно один чек. Ключ — `external_id` АТОЛ = id нашего чека |
| Эвотор, Штрих-М и прочие | Не берём |
| Юрлицо и касса | На филиал: свой аккаунт АТОЛ, группа ККТ, ИНН, СНО, место расчётов. Даже если юрлицо одно — так филиалы можно разделить без переделки |
| НДС | Ставка по умолчанию у филиала, у товара можно переопределить. У доставки своя ставка, она уходит в чек услугой |
| Возврат | Кнопка оператора «Пробить возврат» с подтверждением. Отмена заказа сама чек возврата не шлёт |
| Карта своему курьеру | Настройка филиала: курьер с терминалом без кассы — чек наш через АТОЛ; терминал с кассой — по карте не пробиваем, только наличные |
| Курьер Яндекса | Оплату картой фискализирует Яндекс (`fiscalization` в заявке). Мы не пробиваем |
| Каналы (Яндекс Еда) | Чек на стороне агрегатора. Не пробиваем |

## Когда пробивается чек

| Заказ | Оплата | Момент | Чек |
|---|---|---|---|
| Доставка своим курьером | Наличные | Курьер нажал «Вручил» | `sell`, `full_payment`, оплата `0` |
| Доставка своим курьером | Карта, терминал без кассы | «Вручил» | `sell`, `full_payment`, оплата `1` |
| Доставка своим курьером | Карта, терминал с кассой | — | Не пробиваем |
| Доставка Яндексом | Карта курьеру | — | Пробивает Яндекс |
| Самовывоз, зал | Наличные или карта | Оператор выдал заказ (`ready → completed`) | `sell`, `full_payment` |
| Касса ([pos.md](pos.md)) | Наличные или карта | Экран оплаты | `sell`, `full_payment` |
| Онлайн-оплата (потом) | ЮKassa | Оплата и передача | Два чека: `full_prepayment` и `full_payment` с зачётом предоплаты |
| Отменён после чека | — | Кнопка «Пробить возврат» | `sell_refund` на сумму исходного чека |
| Чек не пробили вовремя | — | Кнопка «Коррекция» (потом) | `sell_correction`, `type: self` |

Курьер, получив деньги облачной кассой, показывает клиенту QR-код чека на своём экране — 54-ФЗ требует выдать чек в момент расчёта. Чек приходит асинхронно, обычно за секунды.

## Архитектура

```
Заказ завершён / касса / кнопка
  │  Fiscal.issue(order, kind): строка fiscal_receipts (pending) + Oban в одной транзакции
  ▼
Fiscal.RegisterWorker ── Builder (чек ФФД 1.2) ── Provider.register(receipt, settings)
  │  ok    → wait + uuid
  │  error → Provider.classify_error → :permanent | :retry | {:snooze, сек}
  ▼
Callback POST /integrations/fiscal/:provider/:token   или   Fiscal.PollWorker → Provider.fetch
  ▼
done → payload (ФН, ФД, ФПД, ссылка ОФД)   fail → тревога в админке
```

| Модуль | Отвечает за |
|---|---|
| `Fiscal` | Фасад: выпустить чек, возврат, повтор, решение «пробивать ли» по заказу и настройкам |
| `Fiscal.Receipt` | Таблица `fiscal_receipts`: заказ, филиал, вид (`sell`, `sell_refund`, `sell_correction`), стадия (`full_payment`, `full_prepayment`), провайдер, `uuid`, статус, тело запроса, `payload`, ошибка, попытки |
| `Fiscal.Builder` | Заказ → чек ФФД 1.2 без привязки к провайдеру: позиции, доставка, скидка, НДС, оплаты, клиент |
| `Fiscal.Provider` | Behaviour: `key/0`, `name/0`, `settings_schema/0`, `register/2`, `fetch/2`, `classify_error/1`, `handle_callback/2` |
| `Fiscal.Registry` | Список провайдеров, как `Crm.Registry` |
| `Fiscal.BranchSettings` | `branch_info.fiscal`: режим, провайдер, юрлицо, СНО, НДС, email отправителя, карта курьеру, embed на провайдера |
| `Fiscal.RegisterWorker`, `Fiscal.PollWorker` | Отправка и опрос результата. Опрос — если callback не пришёл за 300 с |
| `Integrations.AtolOnline` | Адаптер: токен (24 ч, кэш, обновление на `ExpiredToken`), `sell`, `sell_refund`, `report`, разбор ошибок |
| `PrintTarget` | Нефискальная печать, см. ниже |

### Модель чека

- Позиции из `order_items`. Скидка и акции распределяются в цену позиций пропорционально, остаток копеек — в последнюю. Та же логика уже есть для Яндекс Доставки (`yandex_delivery/claim.ex`) — вынести в общий модуль.
- `sum` позиции ровно `price × quantity`. Если после скидки не делится — позиция дробится на строки.
- Доставка — отдельная позиция «Доставка», `payment_object: 4` (услуга), своя ставка НДС.
- Подарок за 0 ₽ — позиция с нулевой ценой. **Проверить на тестовой среде**, принимает ли АТОЛ.
- Товар с акцизом (`products.excise`: сладкие напитки) — `payment_object: 2`.
- Клиент — телефон заказа, email — если есть у клиента.
- Кассир — сотрудник, который завершил заказ (курьер, оператор), `cashier` ФИО.
- Суммы в рублях с копейками, `Decimal`, не `float`.

### Настройки филиала

| Поле | Что |
|---|---|
| `mode` | `own` / `external` / `off`. При CRM по умолчанию `external` |
| `provider` | `atol` |
| `atol.login`, `atol.password`, `atol.group_code` | Из «Настроек интегратора» в кабинете АТОЛ, пароль `redact` |
| `atol.sandbox` | Тестовая среда `testonline.atol.ru` |
| `inn`, `sno`, `payment_address`, `email` | Юрлицо филиала. `inn` и `payment_address` должны совпадать с группой ККТ |
| `vat`, `delivery_vat` | Ставка по умолчанию и для доставки |
| `courier_card` | `receipt` — пробиваем; `terminal` — терминал с кассой, не пробиваем |

У товара — необязательное поле `vat`, перекрывает ставку филиала. Ставка `vat` в настройках Яндекс Доставки переезжает сюда, Яндекс берёт её из `Fiscal`.

Кнопка «Проверить подключение» — `getToken` и сверка ИНН.

## Админка

- Настройки: раздел «Касса и чеки» в настройках филиала.
- Карточка заказа: блок «Чеки» — вид, сумма, статус, ссылка на чек в ОФД, ошибка. Кнопки «Повторить» у `fail` и «Пробить возврат» у пробитого чека.
- Тревога у оператора, если чек `fail` или висит в `wait` дольше 10 минут.
- Страница «Чеки» филиала: список с фильтром по статусу, чтобы найти непробитые за смену.
- Курьер: после «Вручил» — QR-код чека и ссылка, пока чек в `wait` — «Чек формируется».
- Аудит: выпуск, повтор и возврат пишутся в события.

## Тестирование

- Юнит: `Builder` на заказах со скидкой, доставкой, подарком, акцизом; разбор ответов и ошибок АТОЛ через `Req.Test.stub(Delivest.HTTP.Client, ...)`.
- Контрактный тест `@moduletag :atol_contract` по образцу `yandex_eda_contract_test.exs`: реальный `getToken`, `sell`, `report`, `sell_refund` на `testonline.atol.ru` с общими тестовыми данными. Запуск `mix test --only atol_contract`, в CI не входит — АТОЛ может быть недоступен не из России.
- На тестовой среде проверить до реализации:
  - отдаёт ли ошибка 33 (`IncomingExternalIdAlreadyExists`) `uuid` существующего чека — от этого зависит повтор после таймаута;
  - позиция с ценой 0;
  - приходит ли callback и в каком виде;
  - какой `ofd_receipt_url` отдаёт тестовый ОФД.
- E2E: доставка за наличные → «Вручил» → чек `done`. АТОЛ в E2E подменяется локальной заглушкой на порту сервера, тестовая среда из CI может быть недоступна.

## Порядок работ

1. Контрактные запросы к тестовой среде, ответы на вопросы выше.
2. `fiscal_receipts`, `Fiscal.BranchSettings`, ставка у товара, `Builder` с тестами.
3. Адаптер АТОЛ, воркеры, callback, контрактный тест.
4. Триггеры: «Вручил» курьера, выдача самовывоза и зала, исключения (Яндекс, CRM, каналы, терминал с кассой).
5. Админка: настройки, чеки в заказе, повтор, возврат, тревога, страница чеков.
6. QR чека у курьера.
7. E2E.

## Нефискальная печать (кухня, курьер)

- Сейчас: печать из браузера. HTML-шаблоны под ленту 58 и 80 мм, `window.print()`. Без диалога — Chrome с `--kiosk-printing`. `PrintTarget` с реализацией `Browser`.
- Потом: своя программа-агент, управляемая из админки. Тихая печать ESC/POS на USB- и сетевые принтеры, несколько принтеров, автопечать новых заказов. Реализация `PrintTarget` — `Agent`.
