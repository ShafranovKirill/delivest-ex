# Задача: печать и фискализация (54-ФЗ)

Система автономная, без интеграции с POS-системами заведений. Своё фискальное ядро не пишем — свой слой абстракции поверх готовых провайдеров.

## Архитектура

- Единая модель чека по ФФД 1.2.
- `FiscalProvider` — кто пробивает фискальный чек. Адаптеры подключаемые, новый добавляется без переделки ядра.
- `PrintTarget` — нефискальная печать.
- Ставка НДС, СНО и прочие фискальные параметры — в настройках заведения, не константами в коде.

## Решения

| Вопрос | Решение |
|---|---|
| Основной провайдер | АТОЛ Онлайн (облачная касса). Покрывает и онлайн-оплату, и оплату курьеру |
| Онлайн-оплата | ЮKassa — чеки через эквайринг, когда подключим онлайн-оплату |
| Второй облачный провайдер | OrangeData, Комтет — пока не делаем, архитектура должна позволять добавить |
| POS (iiko, r_keeper и др.) | Не интегрируемся |
| Какие заказы | Чеки только по заказам нашего приложения |
| Заведения на CRM | Настройка заведения `fiscalization: own \| external \| off`. При Frontpad или iiko — `external`, чеки на их стороне, мы не пробиваем |
| Дубли | Один платёж — ровно один чек. Уникальный ключ операции |
| Эвотор, Штрих-М и прочие | Не берём |

## Нефискальная печать (кухня, курьер)

- Сейчас: печать из браузера. HTML-шаблоны под ленту 58 и 80 мм, `window.print()`. Без диалога — Chrome с `--kiosk-printing`. `PrintTarget` с реализацией `Browser`.
- Потом: своя программа-агент, управляемая из админки. Тихая печать ESC/POS на USB- и сетевые принтеры, несколько принтеров, автопечать новых заказов. Реализация `PrintTarget` — `Agent`.

## Заложить сразу

- Онлайн-предоплата и доставка: два чека — «предоплата 100%» при оплате и «полный расчёт» при передаче заказа.
- Чеки возврата и коррекции.
- Асинхронные статусы чека, очередь и повторы: облачные кассы отвечают не сразу.
- Поле под код маркировки («Честный знак») в позиции чека.

## Бэклог
