# Задача: подключить ЮKassa — онлайн-оплата заказов приложения

Онлайн-оплаты сейчас нет: `payment_method: :online` выставляется только для заказов Яндекс Еды, где платит клиент Яндекса (`paid_online` в `Payments.open/3`). Своей онлайн-оплаты у заказов приложения нет, ЮKassa в коде отсутствует, есть только README и OpenAPI в `integrations/yookassa/`.

Основа: [payments.md](payments.md) (модель `order_payments`, статусы `pending → authorized → paid`), [fiscal-receipts.md](fiscal-receipts.md) (два чека АТОЛ), `integrations/yookassa/README.md`.

## Решения

| Вопрос | Решение |
|---|---|
| Схема | Холд: платёж с `capture: false`, списание при принятии заказа (`payments.md`) |
| Чеки | Свои, через АТОЛ: два чека (`full_prepayment`, затем `full_payment`). В платёж `receipt` не передаём |
| Идемпотентность | `Idempotence-Key` = id нашей оплаты (`order_payments.id`) |
| Вебхуки | Через inbox ([integration-kit.md](integration-kit.md)): событие не проводит оплату дважды |
| Способы | Банковская карта и СБП |
| Магазин | Один магазин ЮKassa (`shop_id` и ключ) на франшизу, общий для всех филиалов; настройки на уровне франшизы |
| Клиент | Редирект на страницу оплаты ЮKassa (`confirmation.type: redirect`), возврат на страницу заказа |
| Порядок | Заказ создаётся до оплаты, в статусе «Ожидает оплаты» (подпись в админке и на клиенте), после холда становится обычным |
| Подтверждение | Галочка «Не звонить клиенту» (п.0): оплаченный заказ принимается сам, клиент видит «Заказ принят, начали готовить», при изменениях звонит оператор |
| Включение | Галочка «Онлайн-оплата (ЮKassa)» в разделе «Финансы → Оплата» админки, по филиалам. Без неё на клиенте только наличные и карта курьеру |

## 0. Раздел «Финансы» в админке

Сейчас раздела нет: «Чеки» лежат в группе «Заказы», способы оплаты зашиты в код (`Order @payment_methods`). Создаётся группа «Финансы» в `staff_nav.ex`:

- **Оплата:** способы приёма на филиале (наличные, карта курьеру, онлайн ЮKassa галочками). Онлайн доступна, только если ЮKassa подключена в интеграциях и `health_check` прошёл. Витрина показывает только включённые способы.
- **Чеки:** страница `receipt_live` переезжает сюда.
- В режиме шлюза «Чеки» скрыты, «Оплата» остаётся (онлайн-оплату принимаем мы до CRM), см. [gateway-mode.md](gateway-mode.md).
- Галочка «Не звонить клиенту для подтверждения оплаченных заказов» (по филиалам, только при включённой онлайн-оплате): после успешного холда заказ принимается автоматически и списывается, на клиенте текст «Заказ принят, начали готовить». Без галочки заказ ждёт оператора, как сейчас, и клиент видит «Оператор подтвердит заказ». Если оператор потом меняет состав или сумму, он звонит клиенту; списание проводится на фактическую сумму (частичное списание холда), при отмене холд снимается.
- Права: `finance.read`, `finance.update`.

## 1. Настройки и проверка подключения

- `Yookassa.Settings`: `shop_id`, секретный ключ (`redact: true`), тестовый режим. Уровень настроек: франшиза.
- `Yookassa.Api` через `HTTP.Client` с журналом `:yookassa` и Basic-авторизацией. Все `POST` с `Idempotence-Key`.
- `GET /me`: `health_check` проверяет ключи и читает `fiscalization.provider` (п.6).
- Страница `/staff/integrations/yookassa`, ссылка вебхука, пример по образцу страницы Frontpad.

## 2. Создание платежа

- `POST /payments` с `amount` (рубли с копейками, из `order_payments.amount`), `capture: false`, `confirmation` (редирект на страницу ЮKassa или встроенный виджет, решить по клиентскому приложению), `metadata: {order_id, payment_id}`, `description`.
- Платёж `pending` в `order_payments` до подтверждения клиентом, `external_id` — id платежа ЮKassa.
- Заказ создаётся до оплаты в статусе «ожидает оплаты» или оплата открывается после создания (решить, как лежит в [payments.md](payments.md)); заказ в CRM не уходит, пока оплата не `authorized`.
- Повтор `POST /payments` с тем же `Idempotence-Key` возвращает тот же платёж.
- Тесты: создание, повтор с тем же ключом, ответ с `confirmation_url`.

## 3. Вебхуки и опрос

- События: `payment.waiting_for_capture` (холд готов), `payment.succeeded`, `payment.canceled`, `refund.succeeded`.
- Регистрация вебхуков через `POST /webhooks` требует OAuth-токен, не ключи магазина (OpenAPI). Если OAuth недоступен, ссылка вводится в кабинете руками, настройка показывает инструкцию.
- Приём через `Inbox.accept/4` (идемпотентно по id события). Обработчик перечитывает платёж `GET /payments/{id}` и сверяет статус и сумму, а не верит телу вебхука.
- Опрос зависших `pending` и `waiting_for_capture` (`payments.md`, раздел сверки): задача Oban раз в минуту читает платежи, у которых нет вебхука 2 минуты.
- Тесты: вебхук `waiting_for_capture` переводит оплату в `authorized`; повтор вебхука ничего не меняет; расхождение суммы не принимается.

## 4. Списание и отмена холда

- Принятие заказа (`accepted`) вызывает `POST /payments/{id}/capture` с итоговой суммой, она может быть меньше холда ([payments.md](payments.md), раздел изменений).
- Отмена до принятия: `POST /payments/{id}/cancel`, холд снимается.
- Холд живёт ограниченное время (для карт несколько суток), по истечении ЮKassa отменяет сама, вебхук `payment.canceled` отменяет заказ или возвращает его на оплату.
- Тесты: capture при принятии; отмена заказа снимает холд; истёкший холд.

## 5. Возвраты

- `POST /refunds` с `payment_id` и суммой, `order_refunds` ([payments.md](payments.md)) связаны с оплатой.
- Частичный возврат при правке состава заказа после оплаты.
- Чек возврата `sell_refund` в АТОЛ (п.6).
- Тесты: полный и частичный возврат; повтор того же возврата не удваивает.

## 6. Чеки

Решение: чеки наши, через АТОЛ ([fiscal-receipts.md](fiscal-receipts.md)).

- `GET /me` → `fiscalization`: если у магазина включена фискализация ЮKassa, ЮKassa требует `receipt` в платеже. Тогда либо отключить её в кабинете, либо передавать `receipt` и не пробивать свой чек. Конфликт определяем в п.1 и показываем на странице настроек, чтобы не получить два чека на одну оплату.
- Два чека: при `succeeded` `full_prepayment` (`fiscalized_by: us`), при передаче заказа `full_payment` с зачётом (`type: 2`).
- Тест: оплата фиксирует `fiscalized_by` по настройке; предоплата порождает чек `full_prepayment`.

## 7. Брошенные оплаты и сверка

- Платёж `pending` без подтверждения клиента старше 15 минут отменяется (`POST /payments/{id}/cancel`), заказ уходит из «ожидает оплаты» или отменяется.
- Раз в сутки сверка с ЮKassa (`GET /payments` по периоду): расхождения суммы и статуса в тревогу ([payments.md](payments.md), раздел сверки).
- Тесты: брошенный платёж отменяется; сверка находит расхождение.

## Заказ до оплаты

- Онлайн-заказ создаётся в статусе `created` с оплатой `pending`; в списке заказов и на клиенте подпись «Ожидает оплаты». Кухня, курьеры и CRM его не видят, пока холд не получен.
- Клиента после оформления отправляет на ЮKassa (редирект), назад возвращает на страницу заказа, где статус обновляется по вебхуку.
- Не оплатил за N минут: заказ отменяется с причиной «не оплачен», платёж отменяется (п.7).
- В режиме CRM после холда заказ уходит в CRM как оплаченный, «принят» клиент видит после подтверждения CRM.
- Тесты: заказ без оплаты не доходит до кухни и CRM; вебхук `waiting_for_capture` переводит его дальше; галочка принимает сам; без неё ждёт оператора.
