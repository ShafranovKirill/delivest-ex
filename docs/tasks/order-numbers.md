# Задача: номера заказов

Сейчас `OrderNumber.generate/0` берёт общую последовательность `order_number_seq` и превращает её в `A000…Z999`. После 26 000 заказов на всё приложение буквы кончаются (`[000`, `\000`), а номер общий для всех филиалов.

## Решения

| Вопрос | Решение |
|---|---|
| Сколько номеров | Два: короткий для людей и полный для поддержки и интеграций. Плюс `id` для API |
| Короткий | Счётчик филиала за рабочий день: 1, 2 … 999, 1000. Не кончается, утром снова с 1 |
| Полный | `ГГММДД-КОД-NNN`: `261029-MSK1-042`. Дата первой — номера сортируются по времени |
| Рабочий день | Начинается в 05:00 по времени филиала, как стоп «до конца дня». Заказ в 01:30 — ещё вчерашний день |
| Код филиала | Новое поле `branches.code`: 2–6 символов, латиница и цифры, верхний регистр, уникально |

## Где какой номер

| Где | Номер |
|---|---|
| Экран выдачи, кухня, курьер, «заказ 42 готов» | `42` |
| Карточка заказа в админке | `#42 · 261029-MSK1-042` |
| Клиенту в приложении и push | `42`, в деталях — полный |
| CRM, Яндекс Доставка (`external_order_id`), чеки, поддержка | Полный |
| Поиск в админке | По обоим и по номеру канала |

## Модель

| Поле | Что |
|---|---|
| `orders.business_date` | Рабочий день заказа, `date` |
| `orders.daily_number` | Короткий номер, `integer` |
| `orders.number` | Полный, `string`, уникальный |

- Счётчик — таблица `order_counters (branch_id, business_date, value)`. В транзакции создания заказа: `INSERT … ON CONFLICT DO UPDATE SET value = value + 1 RETURNING value`. Строка блокируется до коммита, поэтому номера филиала идут без дыр и без гонок, а откат транзакции откатывает и номер.
- Уникальность — `(branch_id, business_date, daily_number)` и `number`.
- Короткий номер дополняется нулями до трёх знаков только в полном номере: `042`, `1042`.
- `order_number_seq` и `OrderNumber` с буквами удаляются.

## Перенос

- `branches.code` заполняется из `slug` (верхний регистр, обрезка до 6), конфликты — суффиксом. Поле обязательное в форме филиала.
- Старые заказы: `business_date` и `daily_number` пересчитываются по `inserted_at`, полный номер собирается заново. Старый номер сохраняется в аудите миграции. Номера уже ушли в Frontpad и Яндекс — поиск по старому номеру остаётся через `crm.external_number` и `channel.external_number`.
- Перенос делать вместе со сжатием миграций, см. память «Squash migrations after release».

## Затрагивает

- `Oms.Orders.Create` — шаг `:number`.
- Экран выдачи (`pickup_board.ex`), кухня, страница курьера, push, письма — короткий номер.
- Frontpad (`order_payload.ex`), Яндекс Доставка (`claim.ex`), поиск (`orders/search.ex`) — полный.
- Клиент: экран заказа и история.
- E2E: `placeOrder` ищет `Заказ [A-Z0-9]+` — поменять на новый формат.
