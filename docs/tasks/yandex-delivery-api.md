# Задача: Яндекс Доставка — дубль курьера, готовность заказа, оценка цены

Адаптер Яндекс Доставки вызывает курьера на заказ филиала. Основа: `integrations/yandex_delivery/README.md` и [courier-delivery.md](courier-delivery.md). Сверка с документацией (`docs/openapi/`) показала один риск дубля и несколько методов, которые нужны проекту и не используются.

Сделано: п. 1 (повтор `claims/create` с тем же `request_id`, затем `ClaimLookupWorker` по `claims/search`), п. 2 (`should_notify_on_order_readiness` и `claims/set-point-ready` при `ready`), п. 3 (`due` для предзаказов в окне 30–240 минут; кнопка «Оценить доставку» показывает цену, интервал подачи и убыток против `delivery_amount`). Осталось: п. 4, 5, 6.

| 1 | Таймаут `claims/create` | Попытка закрыта `provider_error`, повтор создаёт новую заявку | Два курьера на один заказ | Баг |

## 1. Таймаут `claims/create`

README (раздел «Ограничения»): таймаут на `claims/create` закрывает попытку `provider_error`, а повтор кнопкой создаёт новую попытку с новым `request_id`; если Яндекс всё же создал заявку, возможен второй курьер.

Код это подтверждает: `Couriers.start/2` при `{:error, reason}` вызывает `close(delivery, :failed, :provider_error)`, `request_id` в `Api.create/3` равен `delivery.id`, а следующая попытка создаёт новый `Delivery` с новым `id`.

Документация Яндекса даёт идемпотентность по `request_id`: при таймауте или 5xx повторять с тем же значением (README, таблица сценария). Плюс `claims/search` принимает `external_order_id`.

- Для неоднозначных ошибок (`{:connection_error, _}`, 5xx) `YandexDelivery.start/2` повторяет `claims/create` с тем же `request_id` до двух раз с паузой 2 секунды. Окончательно закрывает попытку только ответ Яндекса или исчерпание повторов.
- Если повторы не дали ответа: попытка не закрывается сразу, а остаётся `searching` без `external_id` и ставится `ClaimLookupWorker` (Oban, повтор через 30 секунд, до 5 минут). Он вызывает `claims/search` по `external_order_id` (номер заказа) и привязывает найденную заявку к попытке. Не нашёл за 5 минут — закрывает `provider_error`, и тогда повтор безопасен.
- Кнопка повтора блокируется, пока идёт поиск.
- Тесты: таймаут, затем успех с тем же `request_id`; таймаут, затем найденная заявка привязана; таймаут без заявки закрывает попытку через 5 минут; повтор не создаёт второй `Delivery`.

## 2. Готовность заказа

В документации есть `claims/set-point-ready` (заказ готов к выдаче на точке отправления) и параметр заявки `should_notify_on_order_readiness`. Курьер видит, готов ли заказ. Сейчас заявка не передаёт параметр и не вызывает метод, а кухня отмечает готовность в приложении (`Kitchen.finish_ready/2`).

- В `Claim.build/3` для точки `source` передавать `should_notify_on_order_readiness: true`.
- Подписчик события `order.status_changed` в `ready` вызывает `YandexDelivery.order_ready/1` (новый необязательный коллбэк провайдера курьеров): `claims/set-point-ready` по активной заявке. Повтор безопасный.
- Заявка создаётся до готовности (режим поиска филиала), метод вызывается, когда кухня готова, даже если курьер ещё ищется.
- Тесты: переход в `ready` вызывает метод; без активной заявки ничего не вызывается; повторный `ready` не повторяет вызов.

## 3. Оценка цены и времени

`offers/calculate` (варианты доставки с ценой и интервалами) и `check-price` в коде не используются, `due` не передаётся ни разу. Заявка создаётся сразу, цена узнаётся после `ready_for_approval`.

- В карточке заказа кнопка «Оценить доставку»: `offers/calculate` показывает цену и интервал подачи.
- Для предзаказов (`cook_by` в будущем, окно 30–240 минут для `express`) передавать `due` так, чтобы поиск начинался вовремя, а не сразу. Если окно не подходит, поиск начинается в момент запуска, как сейчас.
- Предупреждение, если цена доставки Яндекса выше `delivery_amount`, взятой с клиента: оператор видит убыток до подтверждения.
- Не вводить автоматический отказ от вызова курьера по цене: решает оператор.
- Тесты: оценка показывает цену; предзаказ в окне получает `due`; вне окна не получает.

## 4. Платная отмена

Отмена после `pickup_arrived` платная. `cancel_claim/1` берёт `cancel_state` из `claims/cancel-info` и сразу отменяет, не спрашивая оператора (README, «Ограничения»).

- Если `cancel_state` платный, действие требует подтверждения оператора с суммой (из ответа `cancel-info`). Автоматическая отмена при отмене заказа клиентом: заказ отменяется, заявку держим открытой с тревогой «отмена платная, подтвердите».
- Тесты: бесплатная отмена проходит сразу; платная ждёт подтверждения.

## 5. Время прибытия

`claims/points-eta` отдаёт расчётное время по точкам, `claims/performer-position` координаты курьера. Сейчас в `deliveries.details` лежат статус, цена, `eta` из `claims/info`, исполнитель, телефон, ссылка отслеживания.

- В поллере при статусах `assigned` и `picked_up` раз в минуту запрашивать `points-eta` и показывать «Прибудет в …» в карточке заказа.
- Координаты курьера на карте и клиентское отслеживание не делаем: у клиента есть ссылка Яндекса (`tracking_url`).
- Тест: поллер обновляет ETA.

## 6. Наличные

`switch_to_card/1` после создания заявки переводит заказ с наличных на `card_offline` (Яндекс курьер не принимает наличные), изменение пишется в аудит. Клиент оформил заказ на наличные и не знает, что курьер возьмёт карту.

- Решить с владельцем: уведомлять клиента (пуш или СМС) или запретить вызов Яндекса для наличных заказов.
- Если уведомлять: событие `order.payment_method_changed` и текст «Курьер Яндекса принимает только карту».

## Что не делаем

- **`claims/edit`, `claims/return`, `claims/proof-of-delivery-info`, `set-point-ready` для точки доставки, `robot-handover`:** не нужны процессу.
- **`delivery-methods`, `tariffs`:** справочники, тарифы выбираются в `offers/calculate`.
- **`claims/bulk-info`:** опрос уже идёт по журналу.

## Что нужно от Яндекса

Подтверждение, что `claims/search` по `external_order_id` находит заявку после таймаута, и что `should_notify_on_order_readiness` включён для договора. Тестовая среда не умеет `claims/create` (`403 no_permissions`), поэтому пункты 1–3 проверяются на боевом аккаунте с отменой до назначения курьера.
