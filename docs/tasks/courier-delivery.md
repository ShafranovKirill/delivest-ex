# Задача: строгие статусы заказа и модуль доставки

Статус заказа становится конечным автоматом: только вперёд, у каждого перехода есть исполнитель. Поверх него — модуль доставки: поиск курьера среди своих курьеров или в Яндекс Доставке, отдельная роль курьера со своей страницей.

## Решения

| Вопрос | Решение |
|---|---|
| Откат статуса | Нельзя. Только администратор с правом `orders.revert`, причина обязательна, пишется в аудит |
| Пропуск этапа | Людям нельзя, только на следующий этап. CRM может перескочить — недостающие переходы дописываются с источником `crm` |
| Отмена | Оператор и канал (Яндекс Еда). Отмену каналом оператор видит тревогой и подтверждает, что ознакомился |
| Кто вёл заказ | Каждый переход хранит исполнителя: оператор принял, повар готовил, курьер вёз |
| Филиал на Frontpad | Доставку ведёт Frontpad (у него своя интеграция с Яндекс Доставкой). Наш поиск курьера не запускается |
| Источник курьеров | В настройках филиала: свои курьеры или Яндекс Доставка |
| Свои курьеры | Заявку видят все курьеры филиала. Взял один — у остальных она пропадает |
| Отказ курьера | До «Забрал». Заказ снова уходит в поиск |
| Несколько заказов | Курьер может взять несколько |
| Вручение | Курьер отмечает «Вручил» — заказ завершён. Для наличных и терминала этим же подтверждает получение оплаты |
| Когда искать курьера | Настройка филиала: «Вручную» / «Когда начали готовить» (по умолчанию) / «Когда готов». Кнопка «Найти курьера» у оператора есть всегда |
| Карта у курьера | Точки «откуда» и «куда» на карте. Карта не подключена — адрес словами |

## Автомат заказа

`created → accepted → preparing → ready → delivering → completed`, из любого незавершённого — `cancelled`.

| Переход | Кто |
|---|---|
| `created → accepted` | оператор, канал (автоподтверждение), CRM |
| `accepted → preparing` | повар, оператор, CRM |
| `preparing → ready` | повар, оператор, CRM |
| `ready → delivering` | доставка («Забрал» курьера, Яндекс), оператор |
| `delivering → completed` | доставка («Вручил» курьера, Яндекс), оператор |
| `ready → completed` | оператор — самовывоз и зал |
| `* → cancelled` | оператор, канал |
| на шаг назад | `orders.revert` с причиной |

Статус меняется только через автомат. Прямая запись `status` в changeset убирается.

Каждый переход — строка в `order_transitions`: заказ, из, в, источник (`staff`, `crm`, `channel`, `courier`, `system`), сотрудник, причина, время. Из неё карточка заказа показывает, кто вёл каждый этап.

## Попытка доставки

Отдельная таблица `deliveries`: одна запись — одна попытка доставить заказ.

`searching → assigned → picked_up → delivered`, выход `cancelled` / `failed`.

- Отказ курьера, «курьер не найден» у Яндекса — попытка закрывается, создаётся новая в `searching`. Заказ назад не идёт.
- Отмена заказа отменяет активную попытку (у Яндекса — `claims/cancel`).
- `picked_up` двигает заказ в `delivering`, `delivered` — в `completed`.
- Провайдер — behaviour с реестром по образцу `Crm.Provider`: `:staff` (свои курьеры), `:yandex` ([integrations/yandex_delivery](../../lib/delivest/integrations/yandex_delivery/README.md)).
- Запуск поиска — по событию перехода заказа, неважно, сделал его повар или CRM.

## Роль курьера

- Права: `orders.cook` (переходы кухни), `orders.deliver` (страница доставки), `orders.revert`. Роли собираются из прав.
- Страница «Доставка» в админке, удобная с телефона, обновляется через PubSub.
- Курьер видит: филиал и адрес забора; адрес клиента с подъездом, этажом, квартирой, домофоном, комментарием; имя и телефон клиента; сумму к получению и способ оплаты.
- Курьер не видит: цены позиций, скидки, акции, чужие заказы.
- Кнопки: «Взять», «Отказаться» (до «Забрал»), «Забрал», «Вручил», «Открыть в навигаторе».

## Каналы

- Яндекс Еда, схема `yandex` — курьер Еды, наш поиск не запускается.
- Яндекс Еда, схема `marketplace` — в наш модуль доставки, как заказ из приложения.
- Яндекс Еда, схема `pickup` и самовывоз — без доставки.

## Этапы

1. Автомат заказа, `order_transitions`, права, перевод всех мест смены статуса на автомат, тревога об отмене каналом, откат с причиной.
2. `deliveries`, провайдер `:staff`, настройки филиала (источник, режим поиска), кнопка «Найти курьера», страница курьера.
3. Провайдер `:yandex`: заявка, подтверждение, опрос журнала, данные курьера, ссылка отслеживания.

## Открыто

- Яндекс Доставка: тестовая среда и лимиты — спросить у менеджера.
- Яндекс не принимает наличные: что делать с заказами за наличные при источнике «Яндекс».
- Нужна ли причина отказа курьера.
- Сверка кассы курьера в конце смены.
- Пуш курьерам о новой заявке и клиенту о курьере.
