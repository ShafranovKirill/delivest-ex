# Задача: экран выдачи заказов

Экран в зале для гостей: какие заказы готовятся, какие готовы. Минимализм — только номера.

Базовый экран и циклическое перелистывание при переполнении реализованы (2026-11-02).

## Решения

| Вопрос | Решение |
|---|---|
| Какие заказы | Зал и самовывоз. Доставка не выводится |
| Что показываем | Красивый номер заказа (`OrderNumber`). Без имён, состава и времени |
| Колонки | «Готовятся» (`preparing`) и «Готовы» (`ready`) |
| Сколько висит в «Готовы» | Пока заказ не выдан (`completed`) или не отменён |
| Когда стал готов | Номер переезжает в «Готовы» с красивой подсветкой и приятным звуком |
| Доступ | Ссылка `/board/:token` без входа. Токен филиала в `branch_info.board_token`, создаётся и перевыпускается в настройках филиала, раздел «Экран выдачи». Старая ссылка после перевыпуска не работает |
| Обновление | Живое, через события заказов филиала, плюс перезагрузка раз в минуту. Нет связи — красный баннер «Нет связи» |
| Порядок | «Готовятся» — по времени заказа, «Готовы» — свежие сверху |
| Звук | Браузер не играет звук без жеста, поэтому на экране кнопка «Звук и на весь экран»: включает звук, полноэкранный режим и не даёт экрану гаснуть. Хук общий с кухней (`kiosk.js`) |
| Подсветка | Новый готовый номер 15 секунд пульсирует зелёным |


## Доработка: циклическое перелистывание при большом количестве заказов

Если все номера не помещаются, экран последовательно показывает их порциями: первая страница → вторая → последняя → снова первая. Цикл продолжается автоматически, без действий гостей или персонала.

### Поведение

- Колонки «Готовятся» и «Готовы» перелистываются вместе одним таймером: страницы меняются одновременно. Если в колонке всё помещается, она остаётся неподвижной.
- Размер страницы определяется фактическим доступным местом в каждой колонке: шириной, высотой, размером карточек и отступами. Показывать только полностью помещающиеся номера, без обрезания строк и без полосы прокрутки. Сохранить крупный читаемый шрифт.
- По умолчанию страница показывается 8 секунд, затем сменяется следующей. После последней страницы автоматически вернуться к первой. На каждой странице сохранять существующий порядок заказов; каждый заказ должен появиться за полный цикл.
- Индикатор страниц не показываем: минимализм, только номера.
- Переключение страниц плавное и короткое, без мигания всего экрана и без изменения высоты/положения колонок. Перелистывание само по себе не воспроизводит звук и не запускает подсветку готовности.
- После появления нового готового заказа сразу показать страницу с ним в колонке «Готовы», воспроизвести существующий сигнал один раз и сохранить подсветку на 15 секунд. Эту страницу удерживать как минимум до окончания подсветки, затем продолжить цикл со следующей страницы. Если новых готовых несколько, приоритет у страницы с самым свежим; остальные обязательно показываются в дальнейшем цикле. Не подавать повторный сигнал при возвращении страницы с тем же заказом.
- При обычных событиях заказов и минутном обновлении данных не сбрасывать цикл на первую страницу. По возможности сохранять текущую страницу по первому видимому заказу, а не только по номеру страницы. Если этот заказ исчез, оставаться на ближайшей допустимой странице. Изменение данных само по себе не перезапускает интервал перелистывания, кроме приоритетного показа нового готового заказа.
- Выполненные и отменённые заказы исчезают сразу, в том числе с невидимых страниц. После уменьшения списка пересчитать число страниц и исправить текущую позицию; пустая последняя страница не должна появляться.
- При входе в полноэкранный режим, изменении размера окна или загрузке шрифтов пересчитывать вместимость. Если места хватает хотя бы на один номер, показывать минимум один; для слишком маленького окна предусмотреть компактное представление, не теряя номера.
- При потере связи сохранять существующий баннер «Нет связи». После восстановления перечитать данные и пересчитать страницы; не объявлять все уже готовые заказы новыми только из-за переподключения.
- Таймеры и наблюдатели размера очищать при закрытии/пересоздании хука. Возврат на страницу не должен создавать несколько параллельных циклов.

### Реализация

- `lib/delivest_web/live/board_live/index.ex`: сохранить полный актуальный список заказов, существующие события, звук и подсветку; разметить карточки и сетку для расчёта вместимости (`data-board-order`, `data-board-grid`), передавать в событии готовности самый свежий заказ.
- `assets/js/hooks/pickup_board.js`: расчёт вместимости по реальному DOM и общий цикл колонок; корректно обрабатывать обновления LiveView и изменение размеров. Не хранить отдельную устаревающую копию заказов. При скрытии страниц из клиентского хука согласовать управление DOM с LiveView, чтобы серверные патчи не сбрасывали видимость.
- `assets/js/hooks/kiosk.js`: сохранить существующие полноэкранный режим, звук и Wake Lock. Общий хук кухни не должен получить перелистывание экрана выдачи случайно.

### Критерии приёмки

- 0 заказов: пустая колонка, нет страниц и ошибок. Все номера помещаются: постоянное отображение без перелистывания и индикатора.
- На один заказ больше вместимости: две страницы, последний номер виден целиком. После последней снова появляется первая.
- Несколько полных страниц и неполная последняя: за полный цикл показан каждый номер, ни один не обрезан и не пропущен.
- Обе колонки переполнены по-разному: обе листаются одним циклом, вместимость у каждой своя.
- Обновление списка, удаление заказа с последней страницы и изменение статуса во время перелистывания не оставляют пустых/устаревших страниц и не возвращают экран постоянно к началу.
- Новый готовый номер становится видимым сразу, звук срабатывает один раз; обычная смена страниц не имитирует новую готовность.
- Полноэкранный режим, изменение разрешения и восстановление связи не ломают вместимость и таймеры.
- Проверить в браузере как минимум 1280×720 и 1920×1080 с количеством заказов, превышающим вместимость в несколько раз. Визуально проверить читаемость на телевизоре.

После реализации дополнены тесты экрана выдачи и проверка браузерного поведения; `mix precommit` выполнен. Статус доработки: реализовано (2026-11-02).
