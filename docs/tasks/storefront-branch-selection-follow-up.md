# Выбор филиала, форма доставки и проверка времени

## 1. Обновить страницу выбора филиала

**Согласованный вариант.** Минималистичный список. В каждой строке только название филиала и статус «Открыто» или «Закрыто». Адрес, карта, группировка по городам и подробное расписание в этот экран не входят.

- В `client/src/modules/branch/views/SelectBranchView.vue` оставить короткий заголовок «Выберите филиал» и один список на удобной для чтения ширине. На телефоне список занимает доступную ширину с боковыми отступами. На широком экране выровнять блок по центру.
- Оформить филиал как целиком кликабельную строку. Название слева, компактный статус справа. Использовать существующие токены цветов и типографику витрины, спокойные границы и одинаковые отступы. Длинное название переносится, статус остаётся читаемым. Для статуса использовать текст и цвет, для фокуса предусмотреть видимый контур.
- Оставить в списке активные филиалы, в том числе временно закрытые по расписанию. Закрытый филиал можно выбрать и посмотреть его витрину. При ручной паузе отображать «Закрыто», если филиал сейчас не принимает заказы. Статус каждого филиала рассчитывать по его собственному расписанию, исключениям, часовому поясу и режиму приёма. При отсутствии данных не выдавать догадку за точный статус. Согласовать отображение с правилами витрины.
- Сохранить текущую навигацию после выбора, обработку ошибки переключения и защиту от повторного клика при загрузке. Предусмотреть состояние загрузки и пустой список. При ошибке оставить список доступным для повторной попытки.

## 2. Привести модалку выбора к тому же виду

- В `client/src/modules/branch/components/BranchSelectModal.vue` использовать тот же компонент строки и тот же расчёт статуса, что и на странице. Текущий филиал отметить галочкой и доступной для скринридера подписью. Дополнительное содержимое в строку не добавлять.
- Оставить заголовок, кнопку закрытия и список. Ограничить высоту списка высотой окна. При длинном списке прокручивается область с филиалами, кнопка закрытия остаётся доступной.
- Сохранить существующее поведение выбора, включая переход и действия, которые сопровождают смену филиала. Закрывать модалку после успешного переключения. При ошибке оставить её открытой. Проверить закрытие по Escape, навигацию клавиатурой и возврат фокуса к кнопке открытия.
- Приёмка для обоих экранов. Проверить узкий мобильный экран и десктоп, длинное название, выбранный филиал, отсутствие филиалов, ошибку переключения и два филиала с разным статусом в один момент. При смене рабочего окна статус обновляется без перезагрузки.

## 3. Убрать две подсказки в форме доставки

- В `DeliveryPane.vue` убрать сообщение «Укажите улицу и дом для доставки», которое показывается сразу, пока адрес неполный. Сохранить обязательность улицы и дома, блокировку подтверждения до готовности адреса и существующую обработку ошибок геокодирования и зоны доставки.
- В `DeliveryAddressForm.vue` убрать подпись «Детали для курьера необязательны». Сохранить поля, их подписи и возможность подтвердить адрес без заполнения деталей. Удалить ключи `addressRequired` и `optionalDetails` из переводов, если после изменения у них нет потребителей.
- Приёмка. Пустой адрес открывается без красного текста. Частичный адрес нельзя подтвердить. Полный адрес в зоне доставки можно подтвердить без деталей. Для адреса вне зоны сохраняется действующее сообщение.

## 4. Довести проверку часового пояса

Базовая реализация из `6b7398c` есть. API отдаёт эффективную зону филиала, клиент использует её для расписания и слотов, а сервер разбирает локальный `cook_by` в зоне филиала корзины и хранит UTC. Правило подстановки на сервере берёт зону франшизы, затем `Europe/Moscow`.

- **Воспроизведённый дефект.** `zonedDate` перекладывает часы филиала в локальный JavaScript `Date`. При `TZ=America/New_York`, зоне филиала `Europe/Moscow` и моменте `2026-03-07T23:30:00Z` функция возвращает локальные 03:30 вместо московских 02:30, потому что 02:30 пропускается на устройстве при переходе на летнее время. Расчёт расписания и слотов зависит от устройства.
- Заменить такой `Date` на представление времени, в котором арифметика расписания не зависит от зоны браузера. Различать момент UTC и локальные дату и время филиала. Применить один расчёт к статусу филиала, недельному и особому расписанию, текущему приёму заказов и выбору слота. Сохранить контракт `cook_by` и правила преобразования на сервере.
- На сервере проверить прямой запрос оформления заказа с прошедшим временем, временем вне расписания или ручной паузой. Проследить путь от контроллера до сохранения, включая смену филиала корзины. Если ограничение реализовано только на витрине, добавить серверную проверку в пользовательский сценарий заказа и вернуть ошибку, которую checkout может показать. Не распространять её на ручные и внешние заказы без проверки их контрактов. Предел в 30 дней сейчас сравнивается по датам UTC в `Oms.Order.validate_cook_by_range/1`. Если предел относится к календарным дням филиала, зафиксировать это тестом и сравнивать обе даты в его зоне.
- Добавить проверки на один и тот же UTC-момент для филиалов в разных зонах, включая разные даты на устройстве и в филиале, ночное окно через полночь, исключение на конкретную дату, смену активного филиала с уже выбранным слотом, переход времени на устройстве и наследование зоны франшизы. В тесте оформления заказа проверить точный UTC для выбранного локального слота. Сверить правила с [исходной задачей по часовым поясам](timezone.md).
- Текущая проверка. Прошли 17 серверных тестов для `LocalTime`, API филиалов, расписания Яндекс Еды и слепка франшизы. Клиентский `pnpm type-check` прошёл. Сценарий перехода времени воспроизведён отдельно на текущей реализации. Сквозная проверка оформления заказа остаётся частью приёмки.

## 5. Сделать доступным слепок всей франшизы и сохранить слепок филиала

- Серверная реализация уже есть в `5e7e000`. В целевой среде проверить версию серверной сборки и видимость раздела «Слепок франшизы» в настройках франшизы под администратором. Проверить маршрут раздела `/staff/franchise/snapshot`, скачивание через `/staff/franchise/site-snapshot` и загрузку через интерфейс. Локальная проверка кода не устанавливает, какая сборка развёрнута.
- Выполнить [отдельную задачу на рефакторинг слепка всей франшизы](franchise-site-snapshot-refactor.md). Один архив должен содержать филиалы всей франшизы и выбранные разделы. Исправить повторный импорт общего каталога, независимость раздела интеграций и очистку кэша после коммита.
- Сохранить отдельный слепок в настройках филиала. В админке явно различать область выгрузки. Проверить экспорт и импорт каждого типа под администратором, отказ без прав, импорт в другой инстанс и сохранение данных филиалов вне архива.
