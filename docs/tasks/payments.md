# Задача: оплаты заказа

Сейчас оплата — одно поле `orders.payment_method` (`cash`, `card_offline`, `online`). Нет факта оплаты, суммы, времени, кто принял, внешнего id и возврата. Перед онлайн-оплатой, кассой и чеками оплата становится отдельной сущностью.

## Принципы работы с деньгами

1. **Копейки целым числом**, см. [money.md](money.md).
2. **Движение денег не редактируется.** Оплата и возврат — записи, у которых меняется только статус по своему автомату. Ошиблись — новая запись (возврат, доплата), а не правка суммы.
3. **Состояние заказа по деньгам вычисляется** из оплат и возвратов, а не хранится флагом, который можно забыть обновить.
4. **Идемпотентность на каждом шаге.** Исходящий запрос — с ключом (`Idempotence-Key` ЮKassa = id нашей оплаты). Входящий вебхук — через inbox, повтор не проводит оплату дважды.
5. **Вебхук — сигнал, а не истина.** Пришло уведомление — запрашиваем объект у провайдера и применяем его статус.
6. **Сверка.** Зависшие `pending` опрашиваются задачей. Раз в сутки — сверка наших оплат с провайдером, расхождения в тревогу.
7. **Деньги двигаются только через события в транзакции**, см. [order-events.md](order-events.md). Никаких вызовов провайдера после коммита без задачи.
8. **Двухстадийная онлайн-оплата.** Холд при оформлении, списание, когда заказ принят. Заказ не приняли — холд отменяется, возврат не нужен.
9. **Возврат — только к конкретной оплате** и не больше её остатка.
10. **Кто и когда.** У каждой оплаты и возврата — кто провёл (клиент, курьер, кассир, оператор, система) и момент расчёта. От момента зависит чек.
11. **Чек привязан к оплате или возврату**, не к заказу. Один платёж — ровно один чек прихода.

## Модель

`order_payments`:

| Поле | Что |
|---|---|
| `method` | `cash`, `card` (терминал), `online` (ЮKassa), `sbp`, `certificate`, `aggregator` |
| `amount` | Копейки |
| `status` | `pending → authorized → paid`, `failed`, `cancelled` |
| `provider`, `external_id` | ЮKassa, Яндекс, терминал. Уникально по паре |
| `collected_by_id` | Курьер или кассир |
| `cash_given` | Сколько дал клиент наличными, сдача = `cash_given − amount` |
| `paid_at` | Момент расчёта |
| `details` | Ответ провайдера, маска карты |

`order_refunds`: оплата, сумма, причина, статус, провайдер и внешний id, кто провёл.

Состояние заказа по деньгам (`Payments.balance(order)`):

| Значение | Когда |
|---|---|
| `unpaid` | Оплат нет |
| `partially_paid` | Оплачено меньше итога |
| `paid` | Оплачено ровно итог |
| `overpaid` | Оплачено больше — нужен возврат разницы |
| `refunded` | Всё возвращено |

`orders.payment_method` остаётся как способ, который выбрал клиент: по нему курьер знает, брать наличные или терминал.

## Сценарии

| Сценарий | Оплаты |
|---|---|
| Наличные курьеру | Курьер нажал «Вручил» → `cash`, `paid`, `collected_by` курьер, `cash_given` |
| Карта курьеру | «Вручил» → `card`, `paid` |
| Курьер Яндекса, карта | `card`, провайдер `yandex`, данные из заявки |
| Канал (Яндекс Еда) оплачен | `aggregator`, `paid` при создании |
| Касса, раздельно | Несколько оплат: часть `cash`, часть `card` |
| Онлайн | `online`: `pending` → `authorized` (холд) → `paid` (списание при принятии) |
| Сертификат | `certificate`, частью или целиком |

## Правка оплаченного заказа

Правка разрешена до передачи курьеру, см. [order-changes.md](order-changes.md). После правки пересчитывается долг:

- долг вырос — нужна доплата: онлайн — ссылка на оплату разницы, наличные или карта — курьер возьмёт больше;
- долг стал отрицательным — частичный возврат к последней онлайн-оплате, чек возврата на разницу;
- холд ещё не списан — списывается уже новая сумма (ЮKassa позволяет списать меньше холда).

## Бонусы и сертификаты

| | Бонусы лояльности | Подарочный сертификат |
|---|---|---|
| Что это | Скидка | Предоплата |
| В заказе | Строка скидки, уменьшает итог | Оплата `certificate` |
| В чеке | Цена позиций уменьшена на скидку | Продажа сертификата — чек «аванс». Оплата им — `payments.type: 2`, зачёт предоплаты |
| Возврат заказа | Бонусы возвращаются на счёт | Остаток возвращается на сертификат |

Сами бонусы и сертификаты — отдельные задачи. Здесь закладываем, что оплат у заказа несколько и что есть вид `certificate`. Фискальное оформление согласовать с бухгалтером.

## Курьеры

`couriers/cash.ex` и `settlement.ex` считают по оплатам с `collected_by` курьером, а не по `payment_method` заказа. Расчёт с курьером ссылается на оплаты, которые закрыл.

## Порядок

1. Таблицы, автомат статусов, `Payments.balance`.
2. Существующие заказы: оплата по `payment_method` для завершённых, `paid_at` из перехода в `completed`.
3. «Вручил» и выдача самовывоза создают оплату.
4. Расчёты курьеров на оплатах.
5. Затем касса, чеки, ЮKassa.
