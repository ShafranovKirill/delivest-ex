# Задача: снимок клиента и данные заказа полями

Сейчас `customer_phone` и `customer_name` виртуальные: уходят в `Client`, в заказе только `client_id`. Клиент сменил имя — старые заказы показывают новое. Подменный номер агрегатора с добавочным лежит в `channel.details`. Приборы из Яндекс Еды склеиваются в `comment`.

## Решения

| Вопрос | Решение |
|---|---|
| Контакты в заказе | `orders.customer_name`, `customer_phone`, `customer_email` — как были в момент заказа |
| Связь с клиентом | `client_id` остаётся, по нему история и бонусы |
| Кто читает снимок | Чек, CRM, курьер, Яндекс Доставка, карточка заказа |
| Телефон | E.164 с необязательным добавочным: `+79991234567`, `+79991234567,123`. Строгое `+7XXXXXXXXXX` — только для входа клиента |
| Приборы | `orders.persons`, целое. Яндекс Еда, клиент, CRM — полем |
| Сдача | `order_payments.cash_given`, см. [payments.md](payments.md). Клиент указывает «сдача с» при оформлении |
| Комментарий | Только то, что написал человек |

## Перенос

- Снимок заполняется из `clients` для существующих заказов, для заказов канала — из `channel.details`.
- `OrderComment` Яндекс Еды перестаёт дописывать приборы.
- Frontpad: приборы — поле `person`, если есть, иначе в примечание через `Crm.OrderNotes`.
