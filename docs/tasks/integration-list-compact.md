# Задача: компактный список интеграций

Статус: к реализации. Репозиторий: `server/`. Это изменение представления данных, сформированных в [задаче состояний интеграций](integration-status-and-kitchen-access.md). Семантику проверки связи и включённых функций сохранить.

## Цель

На странице интеграций сейчас сразу видны реквизиты, проверка связи, функции, предупреждения и описания. Список должен помогать быстро найти интеграцию с проблемой и перейти к настройке. Подробные технические сведения остаются на странице соответствующей интеграции.

Точки входа: `lib/delivest_web/live/staff/integration_live/index.ex` (`integration_card/1`, `card_body/1`), `state_components.ex` (`summary/1`), `presentation.ex` (готовое состояние), страницы провайдеров в том же каталоге. Проверить, где ещё используется `StateComponents.summary/1`, прежде чем менять его контракт.

## Шаги и границы

1. Для каждого доступного провайдера в списке оставить название, короткую однострочную оценку состояния и индикатор действия, если есть проблема. Карточка остаётся ссылкой на страницу интеграции. Отсутствие подключения должно быть понятно без чтения технических полей.
2. Убрать из списка строки «Данные подключения», «Проверка связи», список функций, время последней проверки и полный текст предупреждений. На странице провайдера сохранить эти данные и существующие действия. Если часть данных есть только в общей карточке, перенести её на страницу провайдера до удаления из списка.
3. Собрать краткую оценку из существующего `Presentation`, не вводя вторую независимую логику здоровья. Различать как минимум не настроено, работает, требует внимания и проверка ещё не выполнялась. Предупреждение не должно превращать рабочую связь в ложный статус «отключено».
4. Проверить карточки для филиальной и общей интеграции, отсутствующей активной CRM и недоступной по настройкам функции. Сохранять текущие ограничения доступа и маршруты.
5. Добавить понятные подписи для скринридера и видимый фокус ссылки. Длинное название не должно ломать сетку на узком экране.

## Приёмка и проверка

- На типовом экране каждая интеграция занимает компактную карточку с одним статусом. Проблема видна, подробности доступны после открытия.
- Список корректно показывает смешанные состояния нескольких провайдеров. Статус не меняется от одного только сворачивания деталей.
- LiveView тесты покрывают состояния без настроек, после успешной проверки, с предупреждением и с недоступным маршрутом. Проверить мобильную и десктопную ширину в браузере, затем выполнить `mix precommit` в `server/`.
