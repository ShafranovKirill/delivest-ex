## 1 и 11. Время приготовления и режим приёма (готово, кроме паузы каналов)

Корень проблемы один: нет настройки «через сколько заказ готов». Время считается неявно, поэтому ни пауза, ни загрузка, ни предзаказы не могут им воспользоваться.

- Время одно на филиал (см. ниже), отдельных настроек приготовления нет.
- Режим высокой загрузки: добавка в минутах и срок («на 30 минут», «до конца дня»). Витрина и каналы показывают увеличенное время, оператор видит плашку и счётчик до конца.
- Третий режим — пауза: приём закрыт на 15, 30, 60 минут или до открытия, с причиной (нет курьеров, перегрузка, поломка). Витрина показывает «временно не принимаем», каналы получают паузу, открытые заказы не затрагиваются. Снимается по таймеру и вручную, в аудит: кто, на сколько, зачем.
- Для Яндекс Еды использовать готовый механизм `Pause`: загрузка пересылается каналу, если у него есть метод.
- Toast считает throttle отдельно от времени приготовления; нам достаточно одного значения: `время = delivery_time + загрузка`.
- Расчёт времени: одно число на филиал, «от заказа до клиента» — существующее `delivery_time`, второго поля не заводим. Для самовывоза то же число: время до готовности. Режим загрузки добавляет минуты к нему. Ступени по размеру заказа и подсказки по истории не делаем.
- Тесты: добавка увеличивает расчётное время; срок заканчивается — значение возвращается само (Oban `scheduled_at`, не `sleep`).

## 3. Особые часы

- Только исключения по датам. Расписание: исключения по датам (праздник, технический день) поверх недели; хранится рядом с `working_hours`.
- Календарь в настройках филиала, массовое применение к нескольким филиалам.
- Тесты: исключение перекрывает неделю; прошедшие даты чистятся.

## 5. Позиция недоступна внутри заказа

Решено делать. Действие живёт внутри редактирования заказа (настройки заказа), а не отдельной кнопкой на карточке, чтобы не перегружать страницу «Заказы».

- Для заказов без CRM: в форме правки у строки заказа «Нет в наличии» — позиция убирается, сумма пересчитывается, клиенту уходит сообщение (пуш или СМС) с таймером подтверждения.
- Для CRM: недоступно (`OrderLock`); вместо этого — стоп-лист.
- Зависит от [order-changes.md](order-changes.md).

## 6. Расписание самовывоза на клиенте

Сейчас при выборе самовывоза карточка филиала (`PickupBranchCard.vue`, `useBranchSchedule`) показывает расписание на всю неделю. Нужно только сегодня: «Сегодня 10:00–22:00» или «Сегодня выходной», с учётом особых дней из п.3.

## 7–10. Проверить в коде и на макетах

- **Звук и цвета:** есть ли звук нового заказа и подсветка предзаказа (`channel_cancel_alert.ex`, колокол). Если нет — звук + красная точка на разделе, как у Яндекса.
- **Экспорт меню:** импорт таблицей есть, обратная выгрузка нужна для массовой правки.
- **Роли:** готовые наборы «Оператор», «Кухня», «Аналитик», «Менеджер» вместо ручной сборки прав.
- **Отзывы:** вопрос владельцу: нужны ли оценки заказа в своём приложении.

## Что нелогично уже сейчас

- Навигация не знает про режим филиала: «Кухня», «Касса», «Чеки», «Курьеры» остаются при CRM (см. [gateway-mode.md](gateway-mode.md)).
- Пауза есть только у одного канала, хотя нужна всему филиалу.
- Условия `is_nil(@order.crm)` разбросаны по шаблонам карточки заказа.

## Чем не вдохновляться

- Платная реклама и позиция в выдаче (Яндекс Еда): у нас своя витрина.
- Конкурентный анализ и рекомендации: нет данных.
- Склад, закупки, списания (Dodo IS, iiko): вне проекта, остатки — только простые `stocks`.

## Сделано

- Режим приёма филиала (`Delivest.Intake`): загрузка (добавка минут на срок), пауза (приём закрыт на 15, 30, 60 минут или до конца дня, с причиной). Срок кончается сам по времени, возврат в обычный режим — вручную в один клик. В аудит: кто, на сколько, зачем.
- Время филиала `delivery_time` в API и в расчёте дедлайнов — с добавкой. В API карточки филиала поле `intake`.
- Клиентский заказ при паузе отклоняется (`422 branch_paused`), на витрине красный баннер.
- Меню «Приём заказов» и плашка на странице «Заказы».
- Не сделано: пауза для каналов (Яндекс Еда `Pause`) — по раннему снятию паузы неясно, какие блокировки наши; «до открытия» заменено на «до конца дня».
